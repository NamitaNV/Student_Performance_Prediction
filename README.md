# Student Performance Prediction using Machine Learning

Predict a secondary student's final score from their study habits, attendance and
prior achievement. Built as an end-to-end regression pipeline: synthetic data
generation, preprocessing, model comparison, evaluation with MAE / R², a
CLI for scoring a single student, and a Streamlit dashboard over the same
saved model.

**Tech:** Python 3.10+, Pandas, NumPy, Scikit-learn, Matplotlib, Joblib, Streamlit, pytest

---

## Quick start

```bash
pip install -r requirements.txt

python train.py                 # generate data, train 4 models, evaluate, save artifacts
python train.py --tune          # same, with grid-search tuning for RF / GB / Ridge
python predict.py --study-hours 14 --attendance 0.94 --previous-score 78
streamlit run app.py            # interactive dashboard
python -m pytest -q             # 21 unit tests
```

`train.py` prints a full report, writes `artifacts/model.joblib` +
`artifacts/model_metadata.json`, saves `artifacts/metrics.json`,
`artifacts/model_comparison.csv`, `artifacts/report.md` and nine PNG figures in
`artifacts/figures/`.

## Data

`data/students.csv` is generated by `student_perf/generate_dataset.py`
(2,000 students, `seed=42`). The score is a noisy, non-linear function of the
features — attendance, study hours and prior scores matter most, with a small
interaction between study time and attendance — so linear and tree models are
both meaningful candidates. The generator is fully seeded, so results are
reproducible. To use real data instead:

```bash
python train.py --data path/to/your_dataset.csv
```

Your CSV must contain these columns (extra columns are ignored):

| Group | Columns |
| --- | --- |
| Identity | `student_id` (optional, dropped) |
| Numeric | `grade`, `age`, `study_hours_per_week`, `attendance_rate`, `absences`, `previous_score`, `assignments_completed`, `assignment_score`, `sleep_hours`, `extracurricular_hours`, `class_size`, `teacher_quality`, `internet_access` (0/1), `tutoring` (0/1) |
| Categorical | `gender`, `school_type`, `parent_education` |
| Target | `final_score` (0–100) |

Missing columns raise an explicit `ValueError` listing what is absent.

## Methodology

1. **Generate / load** the dataset and validate the required schema.
2. **Feature engineering** — three interaction features:
   `study_attendance_interaction`, `study_hours_per_absence`,
   `prior_performance` (mean of previous and assignment score).
3. **Preprocessing** in a single leak-free `ColumnTransformer`:
   numeric → median imputation + `StandardScaler`; categorical → most-frequent
   imputation + `OneHotEncoder(drop='first', handle_unknown='ignore')`.
   Unseen categories and missing values are handled at inference too.
4. **Train/test split** 80/20, shuffled, fixed seed; 5-fold cross-validation on
   the training split.
5. **Model comparison** — `LinearRegression`, `Ridge`, `RandomForestRegressor`,
   `GradientBoostingRegressor`, each wrapped in an identical `Pipeline` so
   preprocessing is refit inside every CV fold.
6. **Evaluation** — MAE, RMSE, R² on the held-out test set, cross-validated
   means, plus a mean-only baseline (predict the training mean) as the bar to beat.
7. **Selection and refit** — lowest-MAE model is refit on all rows and saved
   with a JSON metadata side-car (feature order, seed, target stats, versions).

Everything is in a `Pipeline`, so `predict.py` applies the same imputation,
scaling and encoding that were fitted during training — no manual feature
handling at prediction time.

## Results

Run `python train.py` to regenerate `artifacts/report.md`, which contains the
real numbers for your machine. On the default 2,000-row dataset the expected
behaviour is:

- Mean-only baseline: R² ≈ 0, MAE ≈ the standard deviation of the scores.
- `LinearRegression` / `Ridge`: R² in the high 0.7s / low 0.8s.
- `RandomForest` / `GradientBoosting`: R² ≈ 0.88–0.91, MAE ≈ 3 points.

The synthetic generator has a noise floor of σ = 3.5 points, so R² is capped
around 0.92 — no model should approach 1.0. `gender` is generated with **zero**
effect on the score; if it shows up in the feature-importance plot, that is a
variance artefact worth mentioning in an interview, and a good prompt for the
fairness discussion.

## Prediction

```bash
# defaults fill in anything you omit
python predict.py --study-hours 14 --attendance 0.94 --previous-score 78

# full profile
python predict.py --study-hours 3 --attendance 0.62 --previous-score 55 \
  --absences 14 --sleep 6 --teacher-quality 2 --parent-education high_school \
  --tutoring 1 --gender male --school-type public

# from JSON, or a whole CSV
python predict.py --json student.json
python predict.py --batch students.csv
```

Output shows the predicted score, a performance band (Excellent / Very good /
Good / Needs improvement / At risk) and the offset from the cohort mean in
standard deviations.

## Dashboard

```bash
python train.py          # the app reads artifacts/model.joblib, so train first
streamlit run app.py
```

`app.py` is a thin Streamlit layer over the same code paths as `predict.py` —
it imports `DEFAULTS` / `coerce_types` from there and scores through
`student_perf.persistence.predict_one`, so the UI and the CLI cannot drift apart.
Five tabs:

| Tab | Contents |
| --- | --- |
| Predict | sliders / selects for all 17 raw features, live score, band, position on 0–100, offset from the cohort mean and from the median student |
| What-if | sweeps one feature at a time across its training range and plots the predicted score, so you can see how much each lever is worth |
| Batch | CSV upload, per-row scores and bands, band histogram, download |
| Model | test metrics, model comparison, feature weights (`coef_` or `feature_importances_`), target stats, training metadata, full report |
| Figures | the nine PNGs from `artifacts/figures/` |

`age` is derived from `grade` (plus a "birthday has passed" toggle) because the
generator ties the two together. If you retrain, press **Reload artifacts** in
the sidebar to drop the cached pipeline.

## Tests

`python -m pytest -q` covers the generator schema and bounds, feature
engineering, split reproducibility and disjointness, the preprocessor under
missing values and unseen categories, that the pipelines beat the mean-only
baseline, that the random forest is at least competitive with linear regression,
and the model / metadata save-load-predict round trip.

## Possible next steps

- Swap the synthetic data for a real dataset (e.g. a school registry) and check
  the feature-importance ranking still holds.
- Add gradient boosting with early stopping, or a small MLP, and compare.
- Per-segment error analysis by grade and school type to check the model is not
  systematically worse for one group.
- Quantify uncertainty with quantile regression (predict the 10th/90th
  percentile) instead of a point estimate.
